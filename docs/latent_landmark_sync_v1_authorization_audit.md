### 写入—攻击—盲读

1. 生成路径沿用 `src/cegwm/runtime/content_adaptive_sd35.py:382` 的 `run_sd35_content_adaptive`：20步、最终 PIL RGB；`ContentAdaptiveInjectionCallback` 在零基 step_index=18 执行内容分析和 LF/HF 联合更新。新标记必须加在其返回的 `updated["latents"]` 上，不能加在内容更新前，也不能替换内容分配或私自复用旧模板writer。
2. 本机主checkout的 `.venv/lib/python3.12/site-packages/diffusers/pipelines/stable_diffusion_3/pipeline_stable_diffusion_3.py:1062–1139` 静态源码显示：scheduler.step → callback → 继续循环 → 最终VAE解码。因此标准20次循环在18回调之后尚有19这一次去噪更新。这里只核对了源码，没有运行模型；未来执行须记录实际 timesteps 长度、回调索引序列并断言写入一次、之后恰有一次更新。仓库依赖仅为 `diffusers>=0.31`，不能把本机版本当成外部环境锁定版本。
3. 写入所在扩散latent记为 z。回调探针解码使用 `z / scaling_factor + shift_factor`（同文件 `_decode_callback_latents`），最终解码本机diffusers也采用此式；随后图像处理器输出普通RGB。候选保留最终RGB8边界，不叠加SyncSeal。4种图像分别为plain、content-only、main SyncSeal、candidate。
4. 对最终图施加预先冻结的黑填充、双线性、固定画布旋转。具体旋转实现、角度正方向、中心、输出取整和真实H必须一致冻结；“固定中心”本身还不能唯一确定这些。
5. 盲reader输入仅当前RGB、检测密钥及冻结公共资产。直接复用 `src/cegwm/runtime/observation.py:45` 的 `encode_final_rgb_image`：RGB → image_processor.preprocess → VAE设备/dtype → `latent_dist.mode()` → `(mode-shift_factor)*scaling_factor`，输出NCHW。不得 sample、完整扩散反演或以写入latent代替观测。具体scale/shift值来自冻结VAE配置，本次未加载权重核实数值。未来须断言512×512 RGB与1×16×64×64观测，并固定VAE、processor、版本和通道顺序。
6. 在观测上固定高通、通道身份投影、局部核匹配、分离峰及亚像素细化；不同身份点对提案，联合一对一匹配，至少4身份且满足覆盖，等权拟合仅旋转+平移。歧义/漏点/退化应输出失败原因；不使用真值窗口、内容分数选H或SyncSeal兜底。此部分尚未实现，细节见第3节。

### 坐标—回正—内容重判

- 主线 `geometry_v7/contracts.py:83` 使用整数像素中心 x∈[0,W−1]，归一化为 `2*x/(W−1)-1`。`geometry_v7/r1b.py:373` 接收归一化 observed-to-canonical H，内部取逆生成PIL输出到输入采样参数；回正仅一次，512画布、双线性、黑填充。
- 主线没有新局部标记的 latent→RGB 物理中心映射。设明确选定的latent像素到RGB像素矩阵为 A，则 `H_rgb=A_canonical H_latent A_observed^-1`；再用主线归一化矩阵 N 得 `H_public=N_canonical H_rgb N_observed^-1`。不能直接把latent H交给现有回正器。
- 一个待确认的坐标约定示例是单元中心映射 `x_rgb=8*(x_latent+0.5)-0.5=8*x_latent+3.5`；它不等于端点映射 `511*x_latent/63`，也不等于简单乘8。卷积VAE不能仅由尺寸比证明该约定就是实际信号中心。应以选定约定做M0正负旋转/平移、PIL像素采样验证；跨VAE偏差留待M1/M2测量，不能用真值拟合后暗改正式reader。
- 主线v2入口为 `src/cegwm/runtime/paper_detection_v2.py`，使用连续SyncSeal角点及观测复用；内容决策在 `runtime/blind_detection.py:234`：先计算pre，`pre>tau`直接阳性；否则估一次H，合法时回正，用同一key、scorer、preprocess、阈值计算post，`post>tau`才阳性。几何失败不能产生阳性，运行错误与方法拒绝分开记录。
- 统计含注册key加权分数减去**内部固定16个wrong-key分数的最大值**，不是仅原始LF/HF或任意单个wrong-key（`method/blind_detection.py:77`）。M2额外外部wrong-key查询与这16项有不同用途。
- 所有条件的独立几何读出、pre已通过时的强制post评分只能另列诊断，不能冒充主线实际调用。尤其“clean完整路径不得因回正失去阳性”在pre早退规则下不能检验回正损害；须另报诊断post变化，是否把它升级为额外停止条件由用户决定。
- 现有 `BlindProductionAssets` 强制SyncSeal具体类型，不能把candidate伪装成原生产资产。后续应在独立候选入口保持上述内容判决语义，显式记录新runtime身份和原阈值仅作参考；不得绕开原资产身份约束或宣称继承校准。

## 4. 阶段、分母与停止边界

- **M0**：后续另行授权CPU实施。可检查解析点几何、身份冲突、误匹配/漏点/无信号、核与渲染、H方向和坐标共轭；不能证明跨去噪/VAE/RGB8载体存活。第3节规格确定后才有可重复实现目标。
- **M1**：另行授权真实执行；4新来源×6图=24输出，三个幅度仅此阶段选择。正样本选择后仍保留全部幅度与失败，负对照及wrong-key读取另表。质量、内容保持、4/4可读及开发负对照拒绝须同时满足；无可行窗口则停止该首候选，不扩大参数。四来源完全分离仅是开发现象，无FPR结论。
- **M2**：12新来源×4图×5条件=240图像条件行；48幅底图。条件为clean及−15/−10/+10/+15度black；每种图像、每种条件的分母12。四旋转candidate共48行、candidate含clean共60行，不是60或240个独立来源。负对照也须经过candidate reader来检查虚假接受，SyncSeal另跑原生链。
- 内部16项内容wrong-key、额外外部wrong-key、pre/post、独立几何诊断均为调用记录，不增加独立样本数。外部wrong-key至少12个预固定来源对应键；覆盖哪些图像/条件尚须冻结。缺失/运行错误保留在240行，另列状态，不能删除后重算分母。
- 现有M2每旋转≥10/12正确同步、≥10/12内容完整路径通过、相对SyncSeal每条件最多少1单位可保留为暂定开发条件。通过全部所列条件才可建议进入M3；任何未满足、歧义或运行缺失先报告，不自动追参数。这些数值未证明内容容差、统计非劣效、优势或已验证FPR。
- **M2-D**：先冻结M2盲输出，再对固定全集作oracle H；差分、真值邻域、逐点偏差与微扰均为非盲解释，不能反向改变M2结果。失败子集诊断应明确来源与选择规则。微扰网格须诊断前冻结；不能追结果修改1像素判据。oracle回正是已知坐标下的操作性对照，不是严格数学性能上界。
- **M3**：M2通过后才可提议扩展，仍需相应执行授权。CPU删除已读点仅检验容错；实际裁剪引入尺度，属于明确的新模型扩展。需先冻结尺度范围、提案、插值、取整、可见性和阈值；中心/四角×2保留面积为10条件，若覆盖M2全部48底图则480行，但当前尚未明确执行对象，不能当作已冻结分母。真实裁剪不足4点保留为失败，同步不恢复被删内容。
