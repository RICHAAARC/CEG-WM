# Fixed candidate latent write/read diagnostic

Active scope is now one existing fixed public anchor (seed 741091, RMS .04),
canonical and the exact V2 +10 degree bilinear black-fill renderer. There is no
active layout, amplitude, scale or candidate sweep. The old multi-start RST
prototype remains deprecated in the module and is never used by the entry.

The original ISS content callback runs at step 18, then the fixed anchor is
added; at least one remaining sampling callback must occur. Final RGB is encoded
with the public VAE. A single bounded angle fit [-15,15] keeps scale=1 and
translation=0. One RGB resampling is scored with unchanged V2 content statistics.
The reader accepts no original, embedding latent, residual, prompt, mask or Q/K.
Correlation and a one-degree local peak margin describe signal and local
ambiguity, not watermark decisions or globally unique localization.

`python -m experiments.run_latent_sync_development` prints the no-model plan.
Explicit execution adds `--execute --output <new-directory> --seed <seed>` and
optionally `--prompt <text>`. Dependencies are the existing SD3.5 environment
plus `pip install -e '.[latent-sync]'`; credentials come from HF_TOKEN and
CEG_WM_ROOT_KEY. No execution has occurred as part of implementation.

Per pair: three generations make plain, content-only, and content-plus-anchor.
Old V2 RGB synchronization is applied to content-only, giving four output images.
Three methods x two roles x two conditions produce 12 logical score paths.
The content-only positive images additionally get the identical public anchor
reader (two VAE reader calls), without new content decisions or selecting H.
This tests scene/content correlations when the new anchor is absent. The old
SyncSeal model is loaded only for the V2 reference; failure is retained without
preventing the other methods' analysis. No oracle or tolerance grid is generated.

Each marked image is compared with plain using PSNR/SSIM/LPIPS and 2x2 local
MSE in RGB [0,1], including content/synchronization interaction. Results preserve
positive and negative post scores and their separation, with differences from
content-only. `experiments.select_latent_sync_candidates` is now a compatibility
filename for this descriptive comparison (`--report ... --output ...`), and
emits no winner. The former own-oracle-minus-post loss could reward uniformly
unreadable candidates and has been removed from selection use.

This implementation is a bounded readability probe. It does not yet supply a
demonstrated readout repair distinguishing it from the historical V4/V6 failures.
Until real canonical/rotation measurements show an anchor-specific signal and
useful post-score separation at acceptable final quality, latent synchronization
is not complete. No scale/composite, inversion, Attention, D4, gating, global RST
or crop expansion is part of this active entry. Old oracle/tolerance raw evidence
can be reviewed separately; it is not regenerated by default. No robustness,
fixed-FPR, quality-matched improvement or innovation claim follows from CPU tests.
