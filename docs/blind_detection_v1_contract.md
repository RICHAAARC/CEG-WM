## Production method

The single-image content statistic is exactly

`m(image,key) = registered weighted_joint - max(exact 16 wrong-key weighted_joint)`.

The implementation reuses the accepted content-V9 `blind_weighted_scores`, unchanged wrong-key derivation domain and key normalization, and the ordinary-RGB preprocessing route. Paired Gate B, a paired/null image, and an inherited `tau=0` are absent. Correct-key attribution against exact 16 wrong keys is part of `m`; unwatermarked false-positive estimation is a different experiment with its own numerator and fixed denominator.

`detect_watermark(image,key,assets)` accepts only the current ordinary RGB image, the detection key, and frozen public assets. Its production asset type requires the real `SyncSealTorchScript` adapter, not an arbitrary callable or closure. The API and its core call graph have no original image, U/G pair, paired null, prompt, seed, embed record, private latent, attack, truth label, outcome, or stored H input. Production detection refuses to run if the generated N_dev=256 threshold asset is absent and explicitly rejects a test-only threshold. Local method doubles are confined to `detect_watermark_test_only` plus `BlindTestAssets`; those types cannot enter the production API.

For finite `m_pre > tau_blind`, detection is positive and Geometry is not called. Every finite `m_pre <= tau_blind`, including equality, enters Geometry-Direct; there is no `b_low_blind`. Geometry is called once on the current image. A typed `RELIABLE` or `UNRELIABLE` result may supply coordinates only when `error=None`, `legal=True`, and `basic_observable=True`; a legal, finite, invertible raw `H_observed_to_canonical` then rectifies that same image once. The recovered image is rescored by the same internal scorer, normalized key, preprocessing, public content assets, weighted-joint asset, exact-16 wrong-key derivation, and threshold. Only finite `m_post > tau_blind` is positive; equality is negative. A consistent typed `GeometryStatus.UNSUPPORTED` (`legal=False`, `basic_observable=False`, no H, explanatory error), legal no-H observable result, nonfinite/singular H, and rectification failure are complete fail-closed negatives. `GeometryStatus.ERROR`, contradictory typed fields, unknown status, and content post-score interruption are operational incomplete negatives. There is no retry, D4 search, fallback, proxy RGB, or alternate scorer. SyncSeal logit, H legality, and Reliable never vote positive; Reliable remains an optional nonblocking ablation outside the primary method.

`embed_watermark` is a small injected adapter: it invokes the existing content embed once, validates its final ordinary RGB, then invokes frozen SyncSeal final-RGB embedding once. It does not alter the existing content method or the final-RGB order. Real model objects are injected by an execution caller; this implementation and its tests do not load or execute them.

## Development threshold protocol (prepared, not executed)

Before any score is computed, freeze an ordered, source-stratified roster of exactly 256 independent unwatermarked ordinary RGB base images. It must declare disjointness from Geometry-V7 development data, future paper calibration data, and future paper test data. Unit IDs, base-image IDs, and image references must each be unique. The runner then loads and validates every current ordinary RGB image, rejects any duplicate actual pixel digest, and only then permits scoring. Multiple transforms or aliases of one physical base image cannot count as independent samples. Unit IDs, base-image IDs, source strata, image references, order, and the fixed denominator are hashed into the roster identity.

Each row retains the current-RGB digest, `m_pre`, and exactly one complete Geometry-Direct attempt. If a legal raw H is available, the row retains `m_post`; define `z_i=max(m_pre_i,m_post_i)`. A complete fail-closed legal no-H, typed `GeometryStatus.UNSUPPORTED` invalid-H carrying its explanatory `error`, other invalid-H, or rectification-error row keeps finite `m_pre` and uses `z_i=m_pre_i`, covering later direct-positive risk. Typed `GeometryStatus.ERROR`, including SyncSeal adapter-caught model/runtime exceptions, is an operational interruption and retains its original error; status handling never guesses from error text. Image I/O, pre/post content scorer interruption, model/runtime/GPU interruption, an impossible/unknown Geometry status, a missing row, image/identity/order drift, a nonfinite required value, or an incomplete contract blocks threshold creation without deleting the row or changing 256.

Only after all first-pass 256 rows validate may the runner compute candidate `tau_blind=max_i(z_i)`. Before any asset bytes are written, it reloads the same frozen roster images, verifies the same current-RGB digests, and reruns all 256 through the complete pre-score → threshold route → Geometry/post-score system with the same key and strongly typed public runtime. Each replay row retains fresh pre/post scores plus its actual route/decision/recovery state, and those fields are checked against the candidate tau. The fresh replay must retain 256 complete rows and produce empirical false positives `0/256`; any replay exception, image drift, positive, missing row, or runtime drift blocks creation. Cached `sum(z_i>tau)` remains only an arithmetic cross-check and cannot satisfy this replay gate. The accepted tau is serialized as exact IEEE-754 binary64 big-endian hexadecimal and is bound to the calibration key's public digest and production runtime ID; production detection rejects a different key. The create-only output path is `configs/blind_detection/assets/blind_detection_v1_thresholds.json`. Because N_dev=256 was not executed in this implementation task, that file is intentionally absent; there is no placeholder and no default threshold.

Wrong-key attribution must be run later as an explicitly separate fixed-denominator experiment. It cannot be pooled with or substituted for primary unwatermarked FPR.

## Dedicated calibration handoff (prepared, not executed)

`notebooks/blind_detection_v1_calibration.ipynb` is a dedicated N_dev=256 handoff and does not reuse the N=4 callback notebook. Its first executable cell is exactly the required two-line Drive mount. It checks out detached producer exact `6b08bc8cff5158c8cfced7668249d01e9892e043`, checks exact and clean state before and after installation, requires a GPU, validates and hashes the roster and runtime configuration, verifies the public SyncSeal checkpoint identity, summarizes the public key identity, and then permits the single formal runner attempt. It never embeds a key, image roster, credential, or private input value in the committed notebook.

The external roster JSON has exactly three top-level fields: `units`, `disjoint_from`, and `disjoint_evidence`. `units` is the fixed ordered 256-row roster already enforced by `BlindCalibrationRoster`: every row has a nonempty unit ID, base-image ID, source stratum, and image reference; unit IDs, base-image IDs, and image references are unique. `disjoint_from` is exactly the frozen three-way declaration. `disjoint_evidence` has one nonempty predeclared evidence string for each declaration. The runner validates all of this, then validates the 256 distinct current-RGB pixel digests before constructing the scoring runtime or calling a scorer. I/O or physical-identity failure is retained in `calibration_result.json`. Evidence strings are summarized by digest rather than copied, and post-hoc roster edits are not accepted.

The external runtime configuration has exactly `content_model_id`, `device`, `syncseal_checkpoint`, and `syncseal_checkpoint_sha256`. The first two are fixed to the repository's SD3.5 content route and CUDA execution; the checkpoint is an absolute public-asset path with a lowercase SHA-256 identity. The runner uses repository APIs to construct `ContentCalibrationAssets`, load the committed `WeightedJointAsset` with its sidecar, load `SyncSealTorchScript` from the verified checkpoint, and assemble `BlindProductionAssets`. The formal calibration command has no arbitrary module/callable factory.

The formal `calibrate-and-freeze` command takes separate create-only local paths for `calibration_result.json` and a threshold candidate. Every invoked attempt writes one complete result unless the result path already exists or the process cannot start. The result fixes `denominator=256` and `science_denominator=0`; records producer exact and compact input/configuration summaries; retains every calibration row with `m_pre`, `m_post`, `z_i`, Geometry status, image digest, and original failure state; and retains every fresh replay row, decision, and route. Values used for threshold identity are serialized as exact binary64 hexadecimal. A successful runner result describes only a verified local candidate; it does not claim that the designated Drive threshold was published.

An incomplete first pass or any I/O, content scoring, model/runtime, GPU, Geometry operational, identity, or replay interruption writes `OPERATIONAL_BLOCKED`, preserves all rows reached in the fixed order, and writes no threshold candidate. A complete replay that is not 0/256 writes `METHOD_FAILED`, preserves the candidate tau and all replay rows, and writes no threshold candidate. Only a complete first pass plus a fresh complete 0/256 replay writes a readback-verified local candidate and `CALIBRATION_COMPLETE_THRESHOLD_CANDIDATE_READY`. There is no automatic retry, fallback, row deletion, or overwrite.

The notebook creates a unique Drive run directory and retains only runner stdout, stderr, the complete result, one compact SHA-256 manifest, and the threshold on success. Setup, checkout, installation, import, roster, key, configuration, or runner failures retain their stage and error in that single create-only manifest, with hashes of inputs and artifacts that were available. On success it publishes the result and streams, then the manifest, and publishes the designated Drive threshold last from the verified local candidate. Failure before result or manifest publication cannot leave a designated threshold. Its last cell only rereads and hashes existing files; a later authorization session must perform the independent cloud readback. The notebook has one in-memory runner-attempt guard and exactly one `calibrate-and-freeze` command occurrence.

The notebook reused the repository's existing create-only Colab execution pattern; no prior method semantics were inherited.
