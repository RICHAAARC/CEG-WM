## Production method

The single-image content statistic is exactly

`m(image,key) = registered weighted_joint - max(exact 16 wrong-key weighted_joint)`.

The implementation reuses the accepted content-V9 `blind_weighted_scores`, unchanged wrong-key derivation domain and key normalization, and the ordinary-RGB preprocessing route. Paired Gate B, a paired/null image, and an inherited `tau=0` are absent. Correct-key attribution against exact 16 wrong keys is part of `m`; unwatermarked false-positive estimation is a different experiment with its own numerator and fixed denominator.

`detect_watermark(image,key,assets)` accepts only the current ordinary RGB image, the detection key, and frozen public assets. Its production asset type requires the real `SyncSealTorchScript` adapter, not an arbitrary callable or closure. The API and its core call graph have no original image, U/G pair, paired null, prompt, seed, embed record, private latent, attack, truth label, outcome, or stored H input. Production detection refuses to run if the generated N_dev=256 threshold asset is absent and explicitly rejects a test-only threshold. Local method doubles are confined to `detect_watermark_test_only` plus `BlindTestAssets`; those types cannot enter the production API.

For finite `m_pre > tau_blind`, detection is positive and Geometry is not called. Every finite `m_pre <= tau_blind`, including equality, enters Geometry-Direct; there is no `b_low_blind`. Geometry is called once on the current image. A typed `RELIABLE` or `UNRELIABLE` result may supply coordinates only when `error=None`, `legal=True`, and `basic_observable=True`; a legal, finite, invertible raw `H_observed_to_canonical` then rectifies that same image once. The recovered image is rescored by the same internal scorer, normalized key, preprocessing, public content assets, weighted-joint asset, exact-16 wrong-key derivation, and threshold. Only finite `m_post > tau_blind` is positive; equality is negative. A consistent typed `GeometryStatus.UNSUPPORTED` (`legal=False`, `basic_observable=False`, no H, explanatory error), legal no-H observable result, nonfinite/singular H, and rectification failure are complete fail-closed negatives. `GeometryStatus.ERROR`, contradictory typed fields, unknown status, and content post-score interruption are operational incomplete negatives. There is no retry, D4 search, fallback, proxy RGB, or alternate scorer. SyncSeal logit, H legality, and Reliable never vote positive; Reliable remains an optional nonblocking ablation outside the primary method.

`embed_watermark` is a small injected adapter: it invokes the existing content embed once, validates its final ordinary RGB, then invokes frozen SyncSeal final-RGB embedding once. It does not alter the existing content method or the final-RGB order. Real model objects are injected by an execution caller; this implementation and its tests do not load or execute them.

## Development threshold protocol (prepared, not executed)

Before any score is computed, the committed development roster expands a fixed seed-major cross-product: the ordered 32 prompts in `content_v6_iss_development_v1.jsonl`, then the ordered 32 prompts in `content_v9_calibration_v1.jsonl`, under each of the existing seeds `2026101000` through `2026101003`. This gives exactly 256 unique logical `(prompt identity, seed)` base units and eight source strata of 32. Unit IDs, base-image IDs, source strata, and generated-image references are unique and fixed by Git producer exact plus path and order. The runner mechanically verifies that these pairs do not overlap the four Geometry-V7 reference-development pairs or eight Geometry-V7 evaluation pairs. The complete 256-pair set is reserved exclusively for BlindDetection-V1 development; future paper calibration and test splits must exclude it. Calibration and replay neither compute, retain, nor compare ordinary-RGB digests; alignment is solely the fixed `roster_index`, unit ID, source stratum, order, and deterministic prompt-plus-seed generation contract.

Each row retains `m_pre` and exactly one complete Geometry-Direct attempt. If a legal raw H is available, the row retains `m_post`; define `z_i=max(m_pre_i,m_post_i)`. A complete fail-closed legal no-H, typed `GeometryStatus.UNSUPPORTED` invalid-H carrying its explanatory `error`, other invalid-H, or rectification-error row keeps finite `m_pre` and uses `z_i=m_pre_i`, covering later direct-positive risk. Typed `GeometryStatus.ERROR`, including SyncSeal adapter-caught model/runtime exceptions, is an operational interruption and retains its original error; status handling never guesses from error text. Generation, image validation, pre/post content scoring, model/runtime/GPU, Geometry operational, missing-row, order, nonfinite-value, or incomplete-contract failure blocks threshold creation without deleting the row or changing 256.

Only after all first-pass 256 rows validate may the runner compute candidate `tau_blind=max_i(z_i)`. Before any threshold bytes are written, it reruns the same 256 generated ordinary RGBs through the complete pre-score → threshold route → Geometry/post-score system with the same key and strongly typed public runtime. Each replay row retains fresh pre/post scores plus its actual route/decision/recovery state, and those fields are checked against the candidate tau. The fresh replay must retain 256 complete rows and produce empirical false positives `0/256`; any replay exception, positive, missing row, order mismatch, or runtime interruption blocks creation. Cached `sum(z_i>tau)` remains only an arithmetic cross-check and cannot satisfy this replay gate. The threshold asset carries neither calibration-row, roster, nor replay-row digests and performs no such recomputation; its loader validates the parsed method fields without requiring the input bytes to equal a canonical serialization. The accepted tau is serialized as exact IEEE-754 binary64 big-endian hexadecimal and is bound only to the calibration key's method-intrinsic public digest and production runtime ID; production detection rejects a different key. Because N_dev=256 was not executed in this implementation task, there is no threshold placeholder or default.

Wrong-key attribution must be run later as an explicitly separate fixed-denominator experiment. It cannot be pooled with or substituted for primary unwatermarked FPR.
